# 使用端记忆模块设计

日期：2026-06-12

## 1. 目标

在现有“我的 Claw”静态 Demo 中完整实现个人记忆与组织记忆的使用端体验，覆盖 PRD 的 P0、P1、P2：

- 用户能查看、搜索、筛选、编辑、删除自己的记忆。
- 用户能只读浏览组织授权的记忆库，并主动贡献个人结论。
- 会话过程透明展示记忆的读取、写入、撤销和组织候选提交。
- 召唤专家时可查看并调整交接的记忆，专家返回后可处理记忆建议。
- 用户能整理个人记忆、查看整理历史并回滚。
- Claw 配置展示组织记忆挂载关系。
- 自动化任务可选择是否从执行结果中沉淀记忆，默认关闭。

本次只实现使用端 Demo，不实现管控端审核页面、真实后端、跨设备同步或真实模型推理。

## 2. 产品原则

1. 用户侧只使用“记忆”“我的记忆”“组织记忆”“整理”等概念，不出现 Memory Store、Dreaming、U/C/S/F。
2. 个人记忆默认私有；只有用户明确执行“贡献给组织”或采纳组织候选建议时，内容才进入组织候选。
3. 组织记忆只读，使用端不提供直接编辑能力。
4. 每次写入个人记忆都产生可见事件，并允许立即撤销。
5. 专家收到的个人记忆是只读上下文，不在专家侧留存。
6. Demo 中所有状态变化均在本页内真实生效，刷新后可重置为种子数据。

## 3. 技术方案

### 3.1 模块边界

新增两个独立文件：

- `memory-data.js`：个人记忆、组织记忆库、会话记忆、专家交接、整理历史和通知的种子数据。
- `memory-module.js`：记忆中心页面、弹窗、筛选、编辑、删除、贡献、整理、历史回滚及查询 API。

现有模块只做必要接入：

- `index.html`：增加记忆中心入口、右侧记忆卡片容器、脚本引用。
- `app.js`：增加 `memory` 路由；渲染会话记忆事件、专家交接和建议；驱动右侧记忆卡片。
- `claw-config-module.js`：增加只读组织记忆挂载区，数据来自记忆模块。
- `automation-module.js`：增加 `memory_enabled` 字段和默认关闭的开关。
- `styles.css`：增加记忆页面、事件、卡片、弹窗、整理流程和响应式样式。

`MemoryModule` 对外暴露：

```js
window.MemoryModule = {
  init({ container }),
  render(),
  getMountedStores(),
  getConversationMemory(sessionKey),
  getExpertHandoff(agentId),
  getNotifications(),
  renderConversationEvents(sessionKey),
  renderOverview(sessionKey),
  renderExpertHandoff(agentId),
  renderExpertSuggestions(agentId),
  handleAction(action, payload),
  subscribe(listener)
};
```

`app.js` 不直接修改记忆模块内部数组。它只插入模块返回的 HTML，并将记忆操作转发给 `handleAction`。跨模块变更通过公开方法和 `memory:updated` 自定义事件同步。

### 3.2 状态模型

个人记忆条目：

```js
{
  id,
  content,
  type: "preference" | "decision" | "experience" | "profile",
  sourceSessionId,
  sourceSessionTitle,
  createdAt,
  status: "active" | "pending_org" | "adopted" | "outdated",
  organizationCandidate
}
```

组织记忆库：

```js
{
  id,
  name,
  description,
  maintainer,
  access: "read-only" | "propose-only",
  authorizedBy,
  updatedAt,
  entries: [{ id, title, summary, section, updatedAt }]
}
```

会话记忆：

```js
{
  sessionKey,
  used: [{ memoryId, source, label }],
  remembered: [{ memoryId, kind, label, status }],
  events: [{ id, kind, summary, targetStoreId, status }]
}
```

整理历史：

```js
{
  id,
  createdAt,
  beforeSnapshot,
  afterSnapshot,
  summary,
  changes
}
```

自动化任务增加：

```js
{
  memory_enabled: false
}
```

## 4. 信息架构

设置菜单顺序：

1. 文件
2. 记忆中心
3. Claw 配置
4. 产品说明

`#memory` 是独立页面路由，隐藏 Composer、右侧面板和面板拖拽条，与文件、自动化、Claw 配置等页面一致。

记忆中心包含：

- 页面标题与“整理我的记忆”主操作。
- “我的记忆”与“组织记忆”两个 Tab。
- 搜索、类型筛选、状态筛选。
- 条目列表或组织库列表。
- 整理历史入口。
- 三条隐私承诺。

## 5. 页面与交互

### 5.1 我的记忆

默认展示 38 条的产品语义，但 Demo 种子数据使用足够表达各状态的精简条目，标题计数取当前实际数据。

每条展示：

- 类型标签。
- 记忆内容。
- 来源会话和日期。
- 当前状态。
- 编辑、删除、贡献给组织操作。

交互：

- 搜索匹配内容和来源会话。
- 类型和状态筛选可组合。
- 编辑使用弹窗，保存后立即更新列表。
- 删除需二次确认，删除后更新计数与右侧会话引用。
- “贡献给组织”只展示 `propose-only` 组织库；用户可修改候选内容后提交。
- 提交后状态变为“待组织审核”，生成会话事件和通知。
- 贡献已采纳的条目不重复显示贡献按钮。

空状态：

> 和 Claw 多聊聊，它会记住重要的事。

### 5.2 组织记忆

首层展示被授权挂载的组织库：

- 名称、简介、维护方。
- 条目数、更新时间。
- 权限标识“由组织维护 · 只读”或“可提交建议”。

点击进入库详情，展示索引和分区条目。条目只允许查看，不提供编辑、删除或直接新增。

### 5.3 整理我的记忆

流程分为四态：

1. 确认：说明整理不会直接修改当前记忆。
2. 处理中：显示短暂进度。
3. 结果：显示“整理前 → 整理后”摘要及变更清单。
4. 已应用：写入历史并更新列表。

变更类型包括合并重复、修正过时、删除无用。每条变更均可单独撤销；撤销后重新计算结果摘要。

操作：

- 应用：保存整理前快照和整理后快照，创建历史记录。
- 放弃：关闭流程，不修改数据。
- 整理历史：展示时间和摘要。
- 回滚：恢复对应历史的整理前快照，并新增“已回滚”反馈。

### 5.4 会话记忆事件

在既有消息流中加入灰色居中事件：

- `已记住：{摘要}`，操作为“查看”“撤销”。
- `已向《{组织库}》提交 1 条记忆建议，待管理员审核`，操作为“查看”。
- `你贡献的记忆已被《{组织库}》采纳`，作为异步回执。

查看打开条目详情弹窗。撤销删除对应个人记忆并将事件标记为已撤销。

Demo 故事线通过现有会话步骤和企业智能体会话触发，不新增需要后端的定时器链路。

### 5.5 右侧概览记忆卡片

在“工具调用”之后增加“记忆”卡片，分为：

- 本次用到：个人记忆与组织记忆命中项。
- 本次记住：新写入个人记忆和待审组织候选。

点击条目打开详情。撤销入口仅出现在可撤销的“本次记住”条目。

企业智能体草稿和会话同样展示记忆卡片：

- 草稿态显示准备交接的记忆。
- 执行态显示已交接记忆和专家返回建议的处理状态。

### 5.6 召唤专家记忆交接

召唤普通专家后，在会话流展示确认卡：

- 专家名称。
- “已携带 N 条相关记忆”。
- “调整”入口。
- 提示“专家只读使用，不会保存你的个人记忆”。

调整弹窗按“我的记忆”和“组织记忆”分组，支持勾选增减。至少保留一条时可确认；全部取消时允许继续，但明确显示“未携带记忆”。

专家结果底部展示建议卡，每条包含：

- 建议内容。
- 预判去向：我的记忆或某组织库候选。
- 采纳和忽略。

采纳个人记忆建议会创建个人记忆和灰色事件。采纳组织建议会创建候选和灰色事件。已处理建议不可重复操作。

### 5.7 贡献给组织

入口：

- 我的记忆条目。
- 专家建议卡。
- 会话结论的演示入口。

弹窗步骤：

1. 选择可提交建议的组织库。
2. 编辑候选内容。
3. 查看隐私提示。
4. 提交。

提交后：

- 候选进入待审核状态。
- 页面和会话事件同步。
- Demo 生成一条可手动触发查看的采纳回执通知。

拒绝通知也提供种子数据，用于展示 P2 状态，但不删除原个人记忆。

### 5.8 Claw 配置

在核心文件之后增加“组织记忆”区块：

- 名称。
- 权限。
- 授权人。
- 最近更新时间。
- 说明“挂载关系由组织管理员维护”。

只读展示，不提供挂载、卸载和权限修改。

### 5.9 自动化任务

定时任务和事件任务弹窗都增加：

- 标题：从执行结果中沉淀记忆。
- 开关：默认关闭。
- 说明：开启后只提取可复用结论，执行日志和重复巡检结果不会直接写入。

编辑任务时保留已保存值；新建任务始终默认为关闭。任务列表在说明区展示“记忆沉淀：开启/关闭”。

## 6. 通知与错误处理

- 空搜索结果给出清晰空状态和“清除筛选”操作。
- 编辑内容为空时禁止保存并显示行内错误。
- 未选择目标组织库时禁止提交。
- 删除、回滚等破坏性操作需要确认。
- 整理处理中关闭弹窗会取消当前模拟任务，不修改数据。
- 重复采纳、重复撤销和已删除条目使用幂等处理，不抛出界面错误。
- 模块加载失败时，主页面显示与现有模块一致的降级空态。

## 7. 样式与可访问性

- 复用现有品牌蓝、白色表面、细边框、8-14px 圆角和现有按钮层级。
- 使用现有 SVG sprite 图标，不新增图片或手绘图形。
- 记忆事件保持低干扰灰色，不使用高饱和背景。
- 所有弹窗使用 `role="dialog"`、`aria-modal="true"` 和明确标题。
- Tab、筛选、复选框、开关和操作按钮支持键盘焦点。
- 在窄屏下，独立记忆页面隐藏侧栏并改为单列；弹窗内容单列滚动。

## 8. 验收标准

### P0

- 设置菜单可进入记忆中心。
- 我的记忆支持列表、搜索、筛选、编辑和删除。
- 会话中可见记忆写入事件，并能查看和撤销。
- 右侧概览显示本次用到和本次记住。

### P1

- 组织记忆库和条目可只读浏览。
- 可从个人记忆向有权限的组织库提交候选。
- 召唤专家显示携带记忆，并可调整。
- 专家建议可采纳或忽略，采纳后路由到正确目标。
- 整理流程可预览变更、逐项撤销、应用或放弃。

### P2

- 通知中可展示候选采纳和拒绝回执。
- 整理历史可查看并回滚。
- 自动化任务的记忆开关默认关闭，创建和编辑均可用。

### 回归

- 原有聊天、智能体广场、技能、插件、自动化、文件、Claw 配置和产品说明路由仍可进入。
- 原有设置菜单、账户菜单和未提交的安全治理演示功能不被覆盖。
- 页面无 JavaScript 语法错误，主要交互在浏览器中完成一轮验证。

## 9. 验证方法

1. 使用 `node --check` 检查所有修改后的 JavaScript。
2. 启动本地静态服务器。
3. 使用 Codex 内置 Browser 验证：
   - 记忆中心两个 Tab、筛选和 CRUD。
   - 贡献弹窗和候选状态。
   - 整理、应用、历史、回滚。
   - 会话事件和右侧记忆卡片。
   - 专家交接调整和建议处理。
   - Claw 配置组织记忆区。
   - 自动化任务开关默认值和保存。
4. 检查桌面宽度和窄屏布局。
5. 对照本节验收标准逐项审计。
